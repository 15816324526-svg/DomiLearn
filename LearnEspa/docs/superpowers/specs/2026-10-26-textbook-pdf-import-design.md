# DomiLearn 1.0 教材 PDF 导入设计

## 1. 目的

DomiLearn 1.0 只在用户本机运行，并且只支持教材《现代西班牙语1》。本功能负责把扫描版教材 PDF 稳定地交给 Docling 转换，让用户查看技术意义上的成功或失败，并选择确认使用、重新解析或更换文件。

本功能只解决“PDF 是否成功转换”为 Markdown 和 Docling JSON，不识别教材中的课文、单词或课程关系。拆开两层处理后，问题可以明确归因于上传、OCR、Docling 或之后的内容分类规则。

## 2. 已确认的产品规则

- 用户可以拖放 PDF，也可以点击上传区域打开文件选择器。
- 选择 PDF 后立即解析，不再二次确认。
- 允许文件改名；文件名不用于判断教材内容。
- 1.0 只有一个固定教材位置，内部登记为《现代西班牙语1》。
- 用户只查看成功或失败，不查看、下载或编辑转换正文。
- 成功表示转换流程完成且产物完整，不表示每个字符都识别正确。
- 成功后提供“确认使用”和“重新解析”。
- 失败结果不能确认，只提供“重新解析”和“更换文件”。
- 点击“重新解析”后立即执行，不弹确认框。
- 刷新、关闭或离开前端页面不会中断解析。
- 关闭后端、关闭电脑或进程崩溃会中断解析；下次启动时标记失败，由用户手动重新解析。
- 解析中优先显示真实的已运行时间；只有取得真实页数时才显示页数进度，不伪造百分比。
- 曾经确认过的版本永久保留，1.0 不提供历史版本列表和恢复界面。
- 开发阶段在 VS Code 中分别启动前端和后端，不制作一键启动入口。

## 3. 范围

### 本次实现

- 新增“教材目录”路由和页面。
- PDF 拖放、文件选择、基础校验和上传。
- 后端教材状态、上传、任务查询、确认和重新解析接口。
- 持久化后台解析任务。
- 统一 PDF 转换器接口及 Docling 实现。
- 保存原 PDF、Markdown、Docling JSON、转换报告和日志。
- SQLite 保存教材、原始文件、任务、解析版本和当前有效版本关系。
- 程序重启后的中断任务恢复。
- 自动化测试和五页 Docling 样本集成验证。

### 明确不做

- 不提取、分类或编辑单词与课文。
- 不生成学习计划。
- 不调用 LLM，不使用 Token。
- 不展示完整 Markdown 或 JSON 正文。
- 不支持多本教材。
- 不支持取消、暂停和断点续传。
- 不支持历史版本查看、删除和切换。
- 不进行云端上传、服务器部署和多人并发。
- 不制作一键启动或安装包。

## 4. 用户界面

“教材目录”在侧边栏中从禁用状态改为可访问。

### 空状态

页面中央显示虚线上传区域：“将教材 PDF 拖到这里”“或点击选择文件”“仅支持 PDF，最大 500 MB”。拖入或选择文件后立即校验并上传。

### 解析中

展示固定教材名、原始文件名、文件大小、总页数（能够读取时）、“解析中”、已运行时间，以及“整本教材通常需要 20～40 分钟”的非承诺提示。只有 Docling 能提供真实进度时才展示“已处理 N / 305 页”。

解析中隐藏上传区域，不允许同时创建第二个任务，也不提供取消按钮。

### 等待确认

展示“教材解析成功”和“程序已生成转换结果，内容可能存在少量识别误差”，同时显示文件名、页数、完成时间和产物类型。操作为“确认使用”和“重新解析”。

重新解析复用当前原 PDF，立即创建新任务；此前已确认版本继续有效，直到新版本被确认。

如果已经存在有效版本，页面在展示新任务状态的同时保留一条简洁的“当前仍在使用版本”信息，避免用户误以为原教材已经失效。新任务失败时同样明确提示旧版本仍然可用。

### 已确认

显示唯一教材信息卡：教材名、当前原始文件名、页数、最近确认时间、“已启用”状态和“重新解析”。

### 失败

展示易懂的错误摘要以及“重新解析”和“更换文件”。失败结果不能确认。底层异常栈只进入日志，不直接呈现给用户。

## 5. 系统结构

```text
Vue 教材目录页面
        ↓
FastAPI 上传与状态接口
        ↓
教材导入服务
        ↓
SQLite 任务队列 + 单后台工作器
        ↓
统一 PDF 转换器接口
        ↓
Docling 独立子进程
        ↓
原 PDF + Markdown + Docling JSON + 转换报告
```

统一转换器接口输入 PDF 路径、输出目录和任务上下文；输出转换状态、Markdown 路径、JSON 路径、页数、耗时、警告和错误。将来增加或替换工具时，不修改前端和公开 API。

Docling 在独立子进程中运行，使 OCR 崩溃、超时或高内存占用不会直接拖垮 FastAPI 主进程。后台一次只运行一个转换任务。

## 7. 文件存储与版本

上传文件采用流式写盘并同步计算 SHA-256 指纹。内容完全相同的 PDF 共享一份原始文件。后端生成存储路径，不直接使用用户文件名；原始文件名只作为显示信息。

```text
backend/storage/textbooks/modern-spanish-1/
├── originals/<sha256>/source.pdf
└── conversions/<version-id>/
    ├── document.md
    ├── document.json
    ├── report.json
    └── conversion.log
```

每次解析创建新的版本目录。确认只更新数据库中的当前版本引用，不覆盖历史产物。已确认历史版本永久保留；失败任务保留最近一次日志，更早的不完整临时输出可以清理。

转换先写入临时目录，全部校验通过后再原子性改名为最终目录，避免半成品被误认为成功。

## 8. 数据库模型

### textbooks

- `id`：固定 ID `modern-spanish-1`
- `title`：《现代西班牙语1》
- `current_version_id`：当前确认版本，可为空
- `created_at`、`updated_at`

### source_files

- `id`
- `sha256`：唯一
- `original_filename`
- `stored_path`
- `size_bytes`
- `page_count`
- `created_at`

### import_jobs

- `id`
- `textbook_id`
- `source_file_id`
- `status`：`queued`、`processing`、`awaiting_confirmation`、`confirmed`、`failed`
- `status` 还包含 `superseded`，表示等待确认的结果已被更新的重试或导入取代
- `started_at`、`finished_at`
- `processed_pages`：可为空，只保存真实值
- `total_pages`
- `error_code`、`error_message`
- `display_filename`：本次上传或重试所使用的显示文件名
- `log_path`：任务级日志路径
- `superseded_by_job_id`：取代当前任务的新任务，可为空
- `created_at`、`updated_at`

### conversion_versions

- `id`
- `textbook_id`
- `source_file_id`
- `job_id`
- `converter_name`、`converter_version`、`configuration_version`
- `markdown_path`、`docling_json_path`、`report_path`、`log_path`
- `page_count`、`duration_seconds`
- `confirmed_at`：可为空
- `created_at`

数据库只保存元数据和文件位置，不保存 PDF、Markdown 或大型 JSON 内容。

## 9. API 约定

- `GET /api/textbooks/modern-spanish-1`：教材、当前版本和最新任务状态
- `POST /api/textbooks/modern-spanish-1/imports`：上传 PDF 并立即创建任务，返回 `202 Accepted`
- `GET /api/textbook-imports/{job_id}`：查询任务状态、耗时和真实进度
- `POST /api/textbook-imports/{job_id}/confirm`：确认等待确认的成功版本
- `POST /api/textbook-imports/{job_id}/retry`：复用原 PDF 创建新任务

若已有活动任务，再次创建任务返回 `409 Conflict`。确认非等待确认状态的任务也返回状态冲突。接口响应使用稳定错误代码，前端映射为中文提示。

只有最新的 `awaiting_confirmation` 任务可以确认。用户从等待确认状态点击重新解析时，旧任务先原子性变为 `superseded` 并指向新任务；旧结果继续留在磁盘，但不能再通过 API 确认。已确认历史版本不受影响。数据库事务和状态条件更新必须防止“确认”和“重试”并发时同时成功。

前端在解析页面每三秒轮询任务；页面不可见时降低频率，重新可见后立即刷新。轮询失败只提示连接异常，不把后台任务标记为失败。

## 10. PDF 校验

- 扩展名为 `.pdf`，不区分大小写
- 文件头和解析结果确认为 PDF
- 文件非空
- 最大 500 MB
- 至少一页
- 存储空间足够时才启动解析

“空间足够”定义为：保存上传文件后，目标磁盘剩余空间至少为 `max(2 GiB, PDF 大小的 3 倍)`。该规则是 1.0 的保守保护线，不代表 Docling 必然使用这些空间；检查失败时提示用户释放磁盘空间。

上传失败后清理临时文件，不把整个大文件加载进内存。

## 11. Docling 配置与成功标准

1.0 固定配置：标准 PDF pipeline、扫描页整页 OCR、RapidOCR 中文模型、CPU 执行、关闭远程服务、关闭 VLM 和图片描述、输出 Markdown 与 Docling JSON、两小时超时，并记录 Docling、RapidOCR 和 onnxruntime 版本。

成功必须同时满足：

- Docling 子进程正常结束
- Markdown 存在且可读取
- Docling JSON 存在、可解析且基本结构完整
- JSON 页数与输入 PDF 页数一致
- 转换报告写入成功
- 产物目录完成原子性发布

成功只代表技术转换完成。OCR 字符或表格结构存在误差仍可显示成功，并给出固定提示。

转换不调用 LLM，不产生 API Token 费用。首次安装或首次运行需要下载本地模型；模型就绪后可以离线转换。正式依赖必须包含 onnxruntime。

## 12. 状态恢复与错误处理

应用启动时把遗留的 `queued` 或 `processing` 任务改为 `failed`，错误为“上次解析被中断”。1.0 不自动恢复和续跑。

用户错误类型包括：无效或损坏 PDF、超过大小限制、磁盘空间不足、OCR/Docling 失败、任务超时、输出不完整和上次解析被中断。

报告和日志记录工具版本、配置、开始与结束时间、输入指纹、页数、产物大小、警告和异常摘要，但不记录 PDF 正文。

任务日志从任务创建起写入独立的 `storage/logs/jobs/<job-id>.log`，不依赖成功版本目录。最近一次失败任务的日志永久保留；更早失败任务的数据库元数据保留，但其日志和不完整临时产物可以在新失败出现后清理。

## 13. 前端状态管理

新增教材导入 API 类型与 Pinia 状态。页面以服务端状态为事实来源，刷新时重新请求教材接口。

选择文件后前端立即切换为上传状态；上传成功后使用任务 ID 轮询。上传失败恢复为空状态或保留当前已确认版本，并显示可操作提示。

拖放和文件选择复用同一校验与上传函数。

## 14. 测试与验收

### 自动测试

- PDF 格式、文件头、空文件、页数和 500 MB 限制
- SHA-256 去重和路径安全
- 合法状态转换及非法重复操作
- 同时只能有一个活动任务
- 确认新版本前旧版本仍有效
- 新版本确认后正确切换，历史确认版本仍保留
- 启动时中断任务变为失败
- 超时、子进程异常、产物缺失和 JSON 损坏
- 上传及失败转换临时文件清理
- 前端所有页面状态、轮询、刷新恢复和两种上传方式

普通测试使用假的快速转换器，不启动真实 Docling。

### Docling 集成验证

使用从用户教材截取的五页代表样本验证本地模型、OCR、Markdown、JSON、页数和报告。完整 305 页教材只在最终人工验收时运行一次。

五页样本固定为原 PDF 的第 10、18、19、24、29 页，分别覆盖目录、课文与词汇表、续表与图片、语法、练习。由于教材文件不应提交到代码仓库，样本 PDF 也不提交；本地集成测试脚本从 `TextBook` 中的用户教材按固定页码生成临时样本。教材不存在时，该慢速集成测试明确跳过，普通自动测试仍可完整运行。

相同 PDF 内容以 SHA-256 复用一份源文件，但每个导入任务在 `display_filename` 中保存当次选择的文件名。页面和对应版本显示任务自己的文件名，而不是共享源文件第一次出现时的文件名。

### 用户验收

1. 能拖放和点击选择 PDF。
2. 选择后立即上传与解析。
3. 刷新或离开页面后重新看到真实状态。
4. 成功后确认或立即重新解析。
5. 失败后重新解析或更换文件。
6. 后端保存所有约定产物。
7. 后端重启后把中断任务显示为失败。
8. 全流程不调用 LLM。

## 15. 2.0 扩展边界

2.0 可以保持前端主要流程和公开 API 语义，将 SQLite 换为 PostgreSQL、本地 `storage` 换为服务器磁盘或对象存储、本地单工作器换为服务器任务队列，并加入其他转换器或多教材资源。

1.0 不提前引入 Redis、Celery、Docker 或云存储，只保留清楚的模块边界和稳定数据模型。
