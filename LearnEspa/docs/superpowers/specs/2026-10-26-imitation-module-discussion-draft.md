# 仿写模块讨论稿（待共同确认）

这份文档记录已经确定的体验和仍需决定的实现边界。它不是开发指令。

## 已经确定的产品规则

- 1.0 只有本机一位用户，教材为《现代西班牙语1》；目前数据库已有第一课两篇课文。以后可扩展教材和用户。
- 用户选择一篇教材课文，开启一次新的仿写记录。每次练习必须覆盖该课文的所有句子，按句推进。
- 每句由 AI 结合教材原文、复习池单词、以后积累的句式问题和既往仿写记录，编排一个新情境。用户写一句西语，AI 立即点评具体错误和修改方法；必须改到通过才能进入下一句。
- 原文参考有三种可切换显示方式：完整显示、重点遮挡、完全遮挡。复习池词用于智能编排情境，不作为必须写出的显式目标。
- 同一篇课文和同一句可反复练。再次进入同篇课文时创建新记录并重新调用 Agent 编排；过去每轮、每句、每次修改和反馈都保留，可从复习池入口查看。
- 全篇所有句子通过后结束该轮，AI 生成学习报告。报告的具体栏目后续讨论。
- 希望提供用户填写模型连接信息的页面；至少涉及接口地址、API Key 和模型名称。兼容协议与密钥保存方式尚待设计。

## 现有材料与待处理问题

- 已确认版本的第一课有两篇课文，各约 430 个字符，内容含对话和一段叙述。原始 OCR 有少量缺失重音、误识别的标点。逐句仿写前需把“哪一句是一个练习单位”固定保存，并处理明显识别错误，以免 AI 用错误原文出题或判分。
- 现有仿写页面是演示数据，包含“训练目标”标签、模拟分析进度和模拟报告。这些界面需要依照以上产品规则重做，不能直接把演示题换成一次 LLM 调用。

## 建议的技术模型（未批准实现）

1. **原始记录层**：保存教材版本、课文、句子，以及每轮仿写的编排结果、每次提交的西语句子、AI 反馈与通过结论。记录追加，不以最后一次“对”覆盖之前的错误。
2. **学习状态层**：从原始记录整理“哪些词、句式、原句仍需巩固、最近是否有进步”等状态。例如同一句错两次才通过，可标记“本轮通过、后续仍需巩固”；状态随跨轮表现变化，具体等级和更新规则待讨论。
3. **检索层**：每次出题/点评，只取当前课文句子、相关复习项和少量历史实例交给模型。先用数据库按课文、句子、错误类型检索；教材与记录规模扩大后再评估语义检索。检索加生成是此处 RAG 的实际作用。
4. **Agent 编排层**：为整篇课文制定本轮安排，逐句生成新情境；收到评价后停留在原句或进入下一句，必要时调整提示；全篇通过后调用报告生成。出题、辅导、复盘是三项职责，不预设必须运行三个独立模型进程。

## 下一步讨论顺序

1. 用第一课的一句真实课文，走通“出情境 → 学生写错 → AI 反馈 → 学生改对 → 进入下一句”的纸面例子，并明确通过标准与复核办法。
2. 定义每轮记录及复习池展示方式，再定熟练度标签如何从多次记录更新。
3. 确定模型接口设置、支持范围、每次提交的调用成本与失败恢复。
4. 确认报告内容、Agent 组织方式和 1.0 开发边界，然后写正式设计与实施计划。
