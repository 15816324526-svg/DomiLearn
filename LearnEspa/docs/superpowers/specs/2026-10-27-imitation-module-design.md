# DomiLearn 1.0 教材仿写设计（已确认）

本设计记录 2026-10-26 至 2026-10-27 的产品讨论，已获用户确认并开始实施。适用范围为本机单用户、《现代西班牙语 1》的已确认教材版本，以及 DeepSeek 官方 API。1.0 发布前须覆盖整本教材；开发先用第一课打通闭环，再扩展至全书。

## 1. 要解决的问题

背单词已经能记录错误和复习词。仿写应把教材句式迁移到新的、连贯的中文课文中，并保持所选原文的对话或叙述形式，让学习者逐句写西语、得到具体反馈、改到通过，并在下一轮利用以前的练习记录。整轮、逐句和每次提交都应能回看。AI 应实际参与记忆整理、整篇编排、逐句辅导和报告，而非只生成一次性练习文本。

1.0 的成功体验是：用户设置模型服务，选择教材中任意一课的一篇已确认课文，获得与原文结构相近的一篇中文新课文；完成全部句子后看到有证据的报告；以后从学习报告再次选择同一篇课文，得到新的完整练习。网络或模型出错不能丢掉已写的句子。

## 2. 边界

- 1.0 在用户电脑上运行，一位用户，一本《现代西班牙语 1》。教材课文和词汇来自已确认的转换版本。用户分别启动现有前端和后端。发布前教材仿写须覆盖该书全部 16 课的课文，不能只发布第一课样例；逐课接入是开发顺序，不是发布范围缩减。
- 1.0 接入 DeepSeek 官方 API，使用其 OpenAI 风格接口。仪表盘仍提供 Model ID、URL、API Key 三个可填写字段及“切换服务”；连接测试只接受 DeepSeek 官方地址，其他服务和中转站明确提示“1.0 尚不支持”，其兼容范围留到 2.0。DeepSeek API Key 与 DomiLearn 本地练习数据分别由服务方和本机管理。
- 不增加独立复习池前端页面。词汇复习池仍作为后端数据供记忆 Agent 使用；未来单独设计从薄弱词、薄弱句式或历史仿写记录发起的复习池仿写。1.0 的“仿写练习”和“学习报告 → 再次仿写”均以教材原文为基础，完整覆盖所选课文。
- 不接 MCP，也不要求向量数据库。先从本地数据库按教材、句式和记录检索，交给模型参考。以后教材和用户增多时再评估语义检索与服务器部署。
- 1.0 不提供“换个情景”及练习中途修题。生成前自动审核，少数漏过的问题保留记录，并允许三次未通过后手动通过；换情景和修题作为以后版本的候选。

## 3. 教材句子的准备

现有 `backend/app/models/lesson.py` 中 `Passage` 保存整篇 `content`，尚无固定的逐句练习单位。已完成的 Docling 转换产物覆盖 305 页，识别出第一至第十六课的标题；当前数据库只抽取和保存了第一课的两篇课文及其词汇。这两篇中第一篇主要是对话，第二篇有叙述开头和对话。原始识别存在少量重音和倒问号错误。整本书的课文数量、结构和识别质量仍需逐课核查，不可把“每课两篇”当成固定规则。

实现仿写前，将第一课专用的课文提取流程扩展为全书逐课提取、校验和保存；不能沿用当前只识别第一课边界、且断言恰好两篇课文的规则。每课的提取应产生可核查的篇目、页码、文本和异常报告，缺篇、篇目重复或无法判定边界时不得悄悄标为已覆盖。其余各课的词汇提取也是完整章节“背词→仿写”发布体验的依赖，应与全书课文接入一并规划；在某课词汇尚未完成时，不得虚构该课复习池记录。

为已确认教材版本建立可追溯的练习句记录：原文版本、课文、顺序、说话者或叙述者、校正后的西语文本、原始文本位置、核心句式、固定搭配。明显的 OCR 修正只作用于仿写使用的派生文本，不覆盖用户确认过的原 PDF、转换产物或课文原始记录。同一位说话者连续说多句时仍按一句一题，保留说话者标签。句式和固定搭配需要能追溯到原文；模型提出的结构不能被当作教材事实而不检查。1.0 发布验收须逐课确认所有篇目与句子均已准备好。

原文句式是每道新题的主要学习内容；若原句有固定搭配，新题必须提供自然使用它的机会。人名、具体动作和时态可以随新情景改变，不强求逐字替换。新课文保留所选原文的形式：对话仍是对话；叙述仍是叙述；叙述开头加对话的结构也保留。对话的人物轮次和句子顺序尽量贴合原文。与 `tú`、`usted` 等称呼有关的关系由编排 Agent 根据原句和新情景安排，并在审核时检查一致性。

## 4. 模型服务设置

仪表盘向下滚动后出现“设置模型服务”区域，依次显示 **Model ID、URL、API Key** 输入框和 **“填写完毕，点击测试连接”** 按钮。DeepSeek 官方地址和建议模型可作为填写提示，但三个字段保持可编辑。1.0 明确提示仅支持 DeepSeek 官方接口；输入非官方服务地址时，测试在本地返回“1.0 尚不支持该服务”，不把 Key 发往该地址。官方连接测试发出小型真实请求，可能产生少量服务用量，并验证仿写所需的结构化回复能力，而不只检查网络连通。

- 测试成功：显示“测试成功，服务可用”，将新设置设为生效配置；已生效 Key 不再返回到前端，只显示“已配置”或掩码。
- 测试失败：显示状态码和易懂原因，保留刚填写的草稿以便修改，旧的生效配置继续可用。`200` 是成功；`400`、`401`、`402`、`422`、`429`、`5xx` 等按服务方含义解释。断网或超时没有服务方 HTTP 状态码，不能伪造。错误提示有手动关闭的“×”，不自动消失。
- “切换服务”：清空三个可编辑输入框；旧配置在新设置测试成功前仍生效。新设置生效时替换旧设置，删除旧 Key 的本地保存副本。界面动作不表示 1.0 已兼容中转站。
- 后端负责保存和使用 Key；不得把完整 Key 写入前端包、浏览器持久存储、普通 API 响应或日志。1.0 使用后端控制的本机凭证存储，接口只返回是否配置；2.0 的多用户隔离与服务器凭证保护另行设计。

## 5. 一轮教材仿写

### 5.1 开始与编排

用户从仿写练习或某篇课文的历史报告进入。每篇课文同一时刻最多有一轮未完成练习；再次进入该课文先继续未完成轮次。只有上一轮已完成，才创建新的轮次并重新编排。

开轮前，记忆 Agent 查询该课文、背单词错误形成的复习词、相关句式表现和过去的仿写记录，产出带记录依据的本轮关注点。复习词可以自然融入新情景，但不是每句必须写出的目标词。随后编排 Agent 采用“先规划、再编写”的方式，为每条原文句确定对应的新中文句、说话者、核心句式和适合的复习素材，生成一句简短背景和一整篇连贯的新中文课文。编排计划是可检查的任务结构，不要求保存或展示模型的私有推理。

展示前，程序检查句数、顺序、映射、空值和固定搭配来源；LLM 检查中文课文自然度、场景连贯性、原文形式、句式与搭配是否合适。生成加审核通常至少两次模型调用。未通过时最多自动修改并复查一次；仍未通过就显示可关闭的生成失败提示，不创建正式轮次、不展示未经审核的内容。通过后保存完整计划，整轮情景保持固定，练习中不会按用户表现临时调整尚未展示的句子。用户的表现只影响下一轮。

### 5.2 练习画面

左侧为教材西语原文，允许随时切换完整显示、重点遮挡、完全遮挡三种模式，并设置以后新开轮次的默认模式。重点遮挡应围绕核心句式和固定搭配，不随机遮词。右侧顶部始终显示一行新情景背景；下面每次仅展示当前一句中文及说话者，不提前展示后面的句子。背景本身不算题，也不参与判定。

当前句可主动打开一句简短的情境提示，例如解释说话者关系、礼貌称呼或易混淆的固定搭配。提示先说明场景，不直接给完整西语答案。用户是否查看提示、当时采用哪种原文显示模式都随提交记录保存，供后续解释学习状态。现有演示页的“目标词”标签不能变成强制使用复习池词的判分条件。

### 5.3 提交、反馈和推进

用户写一句西语，后端先保存原样输入及唯一请求标识，再请求辅导 Agent。辅导 Agent 根据当前中文句、场景、教材句式和已有提交给出结构化结果：表达是否符合意思、词汇与语法是否可接受、是否实际用到目标句式、错误原因和可执行的改法。接受多种正确西语表达；纯标点或不影响理解的自然度建议不应阻止通过。重音若改变词义须改正，其余可通过并提示。

- 表达有实质问题：立即显示原句、具体原因、怎样修改；停留在同一句，用户修改后再次提交。
- 意思和语法正确，但用了另一种表达、未练到教材句式：判为通过；解释这一点并示范怎样在当前情景使用教材句式。用户可选择再写一版，也可直接进入下一句。可选改写失败不会撤销先前通过状态。此情况不算词汇或句式错误，记为“该句式尚未实际练到”。
- 使用目标句式且表达正确：判为通过，用户点击“下一句”才推进。
- 同一句获得三次“不通过”判定后，出现“手动通过并进入下一句”。网络错误、超时或无法解析的模型输出不计入三次。手动通过完成该句，但记忆状态标为“掌握情况未确定”，不当作独立用对或确实写错。无须填写理由。

每次提交、反馈、可选改写、手动通过和进入下一句都持久化。请求失败时保存已写句子和当前进度，不推进、不判错；显示有“×”的错误框，用户可重试。暂时离席、刷新或重启后继续当前轮次。已完成的轮次和原始尝试记录不可被下一轮覆盖。

## 6. 记忆、优先级与报告

记忆 Agent 在开轮前整理可用的旧记录，在全篇结束后再次阅读本轮尝试，更新带证据的学习摘要。数据库保留原始答案与反馈；摘要是可重新计算的派生结果。后端检查 Agent 引用的记录是否真实存在，不能凭一段模型文字凭空宣布某句式已掌握。

对一个句式，每轮最多产生一条学习表现证据：在本轮选定的原文显示模式下、未打开可选情境提示而首次正确使用，记 `1`；查看提示或经修改后才正确使用记 `0.5`；尝试但最终未正确使用记 `0`；采用其他正确表达而未尝试、或手动通过，记为“未观察到/不确定”，不纳入表现平均。完整显示、重点遮挡和完全遮挡的结果均记录显示模式；报告只称“该模式下首次用对”，不得把完整原文可见时的成功说成没有参考的独立掌握。1.0 暂不为三种显示模式另设未经验证的数值系数。

1.0 的透明起始算法可参考最近三次**实际使用过句式的不同轮次**，按从旧到新 `1、2、3` 加权：`表现值 = Σ(权重 × 当轮结果) / Σ权重`。无观察记录时不显示分数。只用对一轮标“初步会用”；跨轮连续两次在各自选定显示模式下首次用对、且没有打开情境提示，才标“较熟悉”，并在报告中列明当时的原文显示模式。例如一轮改两次才用对、下一轮首次用对、再下一轮又首次用对，到第三轮才标“较熟悉”。标签与权重是 1.0 的产品规则，不宣称是经统计校准的掌握概率；后续可从原始记录重新计算。

“熟悉程度”和“再练优先级”分开。新课文额外复习内容按以下顺序考虑：近期反复写错的句式；意思答对但尚未练到的教材句式；已跨轮用对而隔一段时间未练的句式。只有能自然融入、且不妨碍本篇教材原句句式时才加入。若下一轮仍是同一课文，原句句式本来就应再次提供练习机会，不因此额外插题。

全部原句完成后，轮次立即标记完成。轮后记忆整理和报告生成失败不应撤销完成状态，可分别重试。报告页列出该教材课文的所有轮次，并可从历史轮次再次开启同篇新练习。报告首页展示：完成句数、首次通过／修改后通过／正确替代表达／手动通过；本轮实际用过及未练到的教材句式；有记录依据的反复问题；与此前同篇练习的变化；下一轮建议。每句明细可展开查看中文题目、每次西语提交和 AI 反馈。后端计算次数和状态，报告 Agent 负责解释；首次练习不强行比较。复习词未写进答案不扣分。报告不展示未经验证的“掌握度百分比”。

## 7. Agent 职责与费用边界

- **记忆 Agent**：开轮检索和解释相关记录，必要时追加查询；轮后依据反馈反思、更新学习摘要。ReAct 式追加检索适合前者，Reflection 适合后者，但是否需要额外模型回合应由真实练习样例验证。
- **编排 Agent**：采用 Plan-and-Solve 式“先列句子映射和约束，再写保持原文形式的整篇中文课文”；生成一句背景、固定的逐句中文内容、可选情境提示；接受一次有上限的审核修正。
- **辅导 Agent**：每次提交按稳定规则判定和给改法。它不负责改变本轮情景，不把正确的替代表达判错。
- **报告 Agent**：根据真实记录撰写可核查的学习报告；不自行捏造练习次数或改写历史。
- **确定性后端**：负责身份与凭证、数据库检索、逐句状态、持久化、请求幂等和计算规则。它不因承担这些工作就被包装成 AI Agent。

基线调用规模为开轮时的记忆整理与整篇生成、展示前审核；每次提交一次辅导调用；结尾一次记忆更新和一次报告生成。审核修正、追加查询、提交重试及可选改写会增加调用。数据库查询、原文遮挡和普通记录保存本身不消耗模型 Token。1.0 应记录每次调用的用途和服务返回的用量，便于用户理解产品运行成本。

## 8. 当前项目与实现验收

现有前端仪表盘、仿写工作台、分析／反馈页及报告页使用演示数据；报告页现有“训练目标未完成”等文案与本设计的正确替代表达规则冲突，需要替换。后端已有教材、第一课课文与词汇、背词会话及尝试表，尚无全书逐课提取、固定练习句、仿写轮次、逐次反馈、记忆摘要、报告和模型连接接口。开发应在现有 `backend` 和 `frontend` 中扩展，运行数据仍保存在 `backend/storage` 的本地目录。

先以第一课真实已确认课文完成以下闭环：设置并测试 DeepSeek → 从教材创建一轮 → 展示一句背景和一题中文 → 写一句、保存、判定、修改或选择正确替代表达 → 点击下一句 → 覆盖全部原句 → 生成报告 → 从历史再次仿写同篇，获得新轮次且旧记录可查。还需验证模型错误不丢草稿、旧配置在新配置测试失败时继续工作、三次真实未通过后可手动通过、人工通过不污染熟悉度、生成审核失败不展示坏题。之后以同一流程完成全书 16 课的课文与逐句数据验收；发布时每课的每篇课文都能开启、完成和再次开启练习，不存在只支持第一课的隐藏限制。其余课程的词汇提取和学习流程也应完成对应章节验收，避免“仿写有课文、背词没有该课数据”的断层。

## 9. 留待以后版本

独立复习池页面及从薄弱项直接发起的专属仿写机制；多教材与多语言；多用户服务器部署；中转站或其他模型服务兼容；换个情景和练习中途修题；根据积累数据调校熟悉度权重；教材与练习规模扩大后的语义检索。这些均不影响 1.0 保存完整原始记录和保留可扩展的教材版本关联。
